# Keep course execution optional for behavioral simulation

Minchan challenged making the exact DSC 10 assignment bundle a prerequisite:
that would tie progress to one course version. The reference execution answered
a narrow environment question and exposed a real runtime error, but recovering
that environment is not the next prerequisite for the broader simulation work.
This corrects the next-step recommendation in the reference-fixture memo.

The immediate research question is: given the visible interaction, tutor reply
and explicitly available task feedback, what next student contributions are
plausible? Asking for more help, submitting revised work and choosing what to
report are candidate behavioral dimensions across tasks. Their plausibility and
frequency are not established by defining a common representation.

Keep task outcomes separate from the student's response to them. For example,
an authored coding scenario can stipulate a failing check; an authored writing
scenario can stipulate rubric feedback that a claim lacks supporting evidence.
Neither requires executing an old notebook to examine a possible next help
request. The supplied feedback must concern the current work and be available
to the student. A scenario condition is an assumption, not a predicted outcome,
an observed student future or proof that the work warrants that feedback.

When feedback is absent, preserve unknown state. Earlier errors do not describe
revised work, and a tutor's suggestion establishes neither an attempt nor its
result. Unknown feedback cannot select success, failure or no-reply. Synthetic
no-reply remains a communication choice; recorded conversation endings do not
establish abandonment or whether work continued elsewhere. After a generated
branch diverges, its historical future cannot supply the missing feedback.

Exact execution remains useful when the question requires a computed result.
Matching assets are needed for reconstruction of the logged environment; a new
course can supply its own execution evidence instead. Fully autonomous rollouts
still need a justified source of task feedback or a separately validated outcome
model. Asking the student LLM to invent that feedback merely hides this unsolved
dependency. Conditional scenarios cannot estimate outcome probabilities or tutor
policy effects, and their results cannot be averaged into a cohort forecast
without justified scenario weights.

Labels continue to describe observable student actions, ordered tutor moves and
their relationships. The current coding-oriented codebook is not a universal
taxonomy. Common definitions are candidates for reuse; course extensions,
classifier reliability and human plausibility require local validation. Chat
alone does not establish hidden effort, emotion, correctness or learning.

The next bounded diagnostic should test supplied feedback versus unknown feedback
on a non-code task using the existing continuation schema and visible-prefix
projection. Keep task feedback separate from dialogue and retain authored
provenance. An invented task can expose notebook-specific assumptions but is
only a contract probe, never an evaluation set. Evidence of transfer ultimately
requires held-out real interactions from another course. Preserve the existing
unknown-state failures; optional execution does not repair them.

No general adapter or executor framework is needed now. The existing grader gate
remains opt-in and specific to grader results; ordinary teacher feedback and
runtime exceptions must not be encoded as failed grader tests. This memo changes
the research direction, not the frozen generators or completed experiments.
